## 1. 时间线

### 11-06 · AgnesCode 逆向 + 变成小弟

- 摸清 AgnesCode = Electron 壳 + `agnesd.exe`（goosed / block-goose 换皮），本地 `https://127.0.0.1:14498` 走 **ACP（Agent Client Protocol）over HTTP**。
- 鉴权是 goose 的 `X-Secret-Key`，密钥每次启动随机生成、只活在进程环境变量 `AGNES_SERVER__SECRET_KEY` 里 → 用 PEB 读进程环境拿到（`PEB+0x20` → ProcessParameters → `+0x80` 是 Environment 指针，长度在 `+0x3F0`）。
- 产出 `D:\tools\agnes-worker\agnes-worker.mjs`：ACP 客户端 + 自动取密钥 + 401 重读；支持 `--task review/summarize/extract/...`、`--digest`（只回一行 JSON）、`--out`（脚本侧落盘，绕开它自己的沙箱）、结果缓存、账本 `--stats`。
- 结论：它能干「读+记录」的活，不能干「判断」的活——扫 7 个文件找 bug，3 条独有里 2 条是假的；给它派活必须带「文件:行号」和「不许猜」。

### 11-06 · 让它变成 DSH 的 subagent

- 插件 `D:\tools\dsh-subagent-agnes`：注册 provider，把 `agnes` 当普通工具用，`--digest` 只回结论行。
- 踩坑：`cordis.patch.yml` 里写裸 `- id:` 会被静默忽略，必须 `- insert:`；写对了会热加载，不用重启。
- 现在可一条消息并发多个 `agnes` 调用（fan-out）。

### 11-08 · aichat 全面审查 + 去 AI 味 + P0 + 上线

- 审查：137 个 Java、35 个测试类、前端 16 个 vue；找出「`createWithReplaces` 无事务导致记忆静默丢失」这类真问题，也证伪了 Agnes 报的 3 条假问题。
- 重构：23 个类改名 `*impl → *Impl`、63 处字段注入改构造器、清教学式注释、14 个测试类去反射；**278 测试全绿**。
- P0：SSE 改 POST、验证码 Lua 原子消费、日限流抽象（`DailyRateLimiter`）、日志脱敏 `MaskUtils`、CORS 配置化。
- 自实现 MCP（Spring AI 1.0-M5 没有 MCP 模块）：`McpClient`（stdio + 换行 JSON-RPC）、`McpToolCatalog`、`McpFunctionCallback`；工具 `now/weather/fetch_url` + 后来 `search`。
- P1 的 12 条人工验收 A~L 全跑完（11 通过 + 1 条文档期望写错），首次部署上线。

### 11-08 ~ 11-09 · 记忆与部署

- 记忆注入按「时间衰减」排序：`score = confidence × 0.5^(闲置天数/半衰期)`，stable 180 天 / dynamic 30 天，查询时现算不落权重。
- 聊天里改/删记忆：规则解析（不用模型）+ 待确认 + before/after；原因是删除不可逆，宁可追问。
- 注册接口（手机号+密码）、deploy.py（打包/上传/迁移/健康检查/备份）、nginx 开 gzip + `Cache-Control: no-cache`。

### 11-10 ~ 11-11 · 任务系统与意图重构

- 任务「闹钟」内核：`@Scheduled` 每分钟扫到期 → `TaskAction`（notify / webhook / mcp / push）→ `tb_task_run` 执行记录；Redis 锁 + `last_notified_at` 防重。
- 记忆维度 `goal` 并成 `fact`（`goal` 和任务语义重复，用户看不出价值）。
- 意图层重构：**从「关键词 + 死提示词 + 固定 JSON」换成工具调用**（`create_task` / `revise_draft` / `remember`）。原因：每加一个 MCP 就要改提示词和代码，用户说得对，这是框架问题。
- 阴影上线：新引擎跑评测 35/40 与旧引擎 87.5% 持平后切默认，删掉 180 行提示词与 4 个旧类。
- 搜索改进：默认抓相关性最高结果的正文，按响应头/`<meta charset>` 解码（修 GBK 乱码），跳过官网首页。

### 11-14 · 能用的最后一公里

- UI 连续修：白屏（模板引用未定义变量）、侧边栏「会话列表消失」（删 tab 时留下裸 `<template>`，子节点不挂载）、登录页首屏 527KB→166KB、设置页/任务页重做、退出登录 token 过期时不跳转。
- 草案可在对话里改：「改成八点半」→ 只回 diff 「时间 09:00 → 08:30」，合并由代码做（模型只填差量）。
- 时间用规则兜底（「明天九点」「后天下午三点半」），防模型漏填。
- 任务「立即运行一次」（不动定时）；README 首屏重写；3 分钟演示脚本。
- 搜索诚实化：结果全是官网首页时明确返回「没查到可核实的内容」，任务记失败，不再假装成功。

## 2. 关键决策（和当时的理由）

| 决策 | 理由 | 代价 |
|---|---|---|
| 记忆只做「隐式上下文」，不做管理面板 | 四类维度是给机器看的，做进 UI 用户看不懂；「明天上早八」会同时进记忆和任务 | 记忆能力对用户不可见，必须靠效果感知 |
| `schedule` 维度删掉 | 和「带时间的任务」语义重复 | 历史数据要迁移（已做） |
| 意图层换成工具调用 | 加 MCP 不用改代码；模型自己组合 | 每轮多一次模型调用，延迟 +1~2s |
| 写作操作一律「先草案再确认」 | 删除不可逆 | 多一步点击 |
| 任务只做「触发器 + 动作 + 记录」，不做通用工作流 | 2C2G 上跑 DAG 是负债；90% 需求是到点提醒/查一次 | 「一句话拆多个任务串起来」没做到 |
| MCP 自己实现 | M5 的 bom 里零 MCP 模块，1.0 要 Boot 3.4 | 协议细节要自己维护 |
| 推送走微信（Server酱 / PushPlus） | ntfy 国内装不上 | 要用户扫码拿 key |

## 3. 踩过的坑（下次直接查这张表）

**Windows / PowerShell**

- `Set-Content` / `Out-File` 写 Java 会加 BOM → `需要 class、interface、enum 或 record`。用 `[IO.File]::WriteAllText(p, t, UTF8Encoding($false))`。
- `pwsh` 的 `cd` 不改变 .NET cwd；`[IO.File]::ReadAllText('相对路径')` 会去 workspace 找。
- `git push` 走 stderr，`$LASTEXITCODE` 可能是 1 但实际成功。
- `PythonIOENCODING` 要在 pwsh 里先 `$env:PYTHONIOENCODING="utf-8"`。
- `Invoke-WebRequest` 按 ISO-8859-1 解 JS，中文 `-match` 永远失败。
- `npm` 被 ExecutionPolicy 拦，用 `node <npm-cli.js>`。

**Spring AI / Java**

- `ChatOptions` 用 `.options(...)` 会**覆盖**默认工具配置 → 模型永远不调工具。别用它设 temperature。
- 工具 schema 里写未转义的 `"` 会让整份 JSON Schema 非法，表现为「模型一次都不调工具」。已加守护测试。
- `@Transactional` 迟到会丢数据（记忆替换：先改旧状态再插新行）。
- ENUM 列写新值被 MySQL 截断（`action_type`），要先改 `VARCHAR`。
- `VARCHAR(512)` 放不下搜索结果，改 `TEXT`。
- 测试里写死日期（`NOW.plusDays(10)`）过几天就红，用 `plusYears`。

**部署 / 运维**

- `deploy.py` 一开始**不上传 `mcp-servers/`**，线上一直跑旧脚本。
- paramiko `exec_command` 里 `nohup ... &` 会随通道关闭被杀，要 `systemd-run --unit=... --collect`。
- 多层引号（pwsh → python → ssh → mysql）必然坏，SQL 从 stdin 传。
- nginx 默认只压缩 `text/html`，JS/CSS 要显式 `gzip_types`；`index.html` 没 `Cache-Control` 会让用户看到旧版本。
- HEAD 请求 nginx 不压缩，用 `curl -I` 判断会误判。

**意图 / 模型**

- 模型输出「看起来对」不等于对：Agnes 会把「没看到」说成「不存在」，报「缺失」必须自己 grep。
- 抽取的确定性不能靠 temperature，要靠提示词 + 确定性兜底（规则）。

## 6. 我这边的判断失误

1. **一直加功能，没守住主线**：记忆四维度、衰减、图标页……用户要的是「聊天 + 到点干活」，我把中间层做厚了。
2. **把「能查」说过头**：搜索只覆盖通用网页查询，赛事这类长尾做不到；应该早点说清边界，而不是做完才发现翻车。
3. **动作链缩水**：答应的是「小工作集串成大工作」，交付的是两个写死步骤。
4. **先做看起来高级的东西**（衰减/维度），后做用户真正感知的东西（列表页、按钮、提示）。

## 7. 如果继续，最小的三件事

1. 把「查不到」的体验做完整：失败时给 3 条带链接的摘要 + 「来源待核实」，而不是一行错误。
2. 任务侧补一个「默认推送通道」设置，让 AI 建任务时能自动带动作链。
3. 压测一轮（wrk/ab 打 `/chat/ask` 与 `/user/tasks`），README 里放一组真实数字——这是面试最容易被追问、也最容易补的。
