# 3 分钟演示脚本

> 目标：让看的人在三分钟内明白「它不是聊天套壳」，而不是把功能念一遍。
> 录制建议：1080p、浏览器 100% 缩放、提前登录好、网络预热（先随便问一句）。

## 0:00–0:20 开场（一句话定调）

讲：

> 这是我做的一个个人 AI 助手。它的特殊之处不是能聊天，而是**聊完之后会留下东西**——
> 记住你的偏好、把话变成任务、到点自己去查数据。而且**写库之前一定让你确认**。

画面：首页 / 空对话。

## 0:20–0:50 记忆：默默记住，不打扰

输入：

```
记住我喜欢简洁一点，别啰嗦
```

讲：

> 注意这里**没有弹窗**。记忆不该打断对话，它只是背景知识。
> 现在再问一个问题，回答明显变短了。

输入：

```
帮我解释一下什么是幂等
```

讲：

> 一次比默认短很多——因为记忆被注入了 system prompt。记忆有 confidence 和半衰期，
> 久不用的会自然降权，不是我手写的规则。

## 0:50–1:40 任务：先给草案，再落库（重点）

输入：

```
明天九点提醒我交作业
```

画面：弹出「草案」卡片（标题 / 时间 / 重复 / 动作）。

讲：

> 它没有直接写库，而是先给我一张草案。如果不对，我可以直接在对话里改。

输入：

```
改成八点半
```

画面：回执「改好了：· 时间：2026-11-15 09:00 → 2026-11-15 08:30」，草案时间变了。

讲：

> 它只报改了什么，没动的字段不会被我一句话带偏。模型只负责填「差量」，
> 合并是我这边的代码做的——这是为了防止"改时间顺手把标题改了"。

点「保存」→ 进任务页看到这条任务。

## 1:40–2:20 到点执行：让它自己去查

输入：

```
每天九点查一下北京天气
```

画面：草案里 `actionType=mcp`、工具 `mcp_info_weather`、参数 `city=北京`。

讲：

> 这类不是"提醒我做某事"，而是"让我去查"。所以它存的是一个 MCP 工具调用，
> 到点由服务端调度器执行——不依赖我开着网页。

确认后，在任务页点**立即运行**（不用等到明天九点）。

画面：执行记录里出现一条「success / 北京: xx°C」。

讲：

> 立即运行只执行一次、不动定时，这样演示不用等。执行记录落库，失败也会记原因。

## 2:20–2:50 动作链（可选，能省则省）

若有微信推送 key：

> 还能串起来：先查，再把结果推到微信。两步之间用 `{{s1}}` 引用上一步输出。

没有 key 就说一句「这条我平时自己用，就不现场演示了」。

## 2:50–3:00 收尾

讲：

> 技术上：Spring Boot 3 + Spring AI + MyBatis + MySQL + Redis，MCP 是自己实现的（Spring AI 1.0-M5 还没有 MCP 模块）。
> 387 个自动化测试、CI 绿、部署在 2C2G 的服务器上。
> 我刻意没做：多 Agent 编排、可视化工作流、更多 MCP——功能堆多了反而讲不清楚。

## 兜底方案

| 意外 | 处理 |
|---|---|
| 模型响应慢 | 提前录一次，剪辑；现场就讲「云端模型，网络因素」 |
| 草案不出现（模型没调工具） | 换一句更明确的：「九点提醒我交作业，标题写交作业」 |
| 推送失败 | 直接跳过这一节，说「推送 key 是私有配置」 |
| 网络断 | 用本地 Ollama 起一份，或放录屏 |

## 时间分配原则

- 拿 80 秒讲**草案 → 改 → 确认**这一段，这是最不像"套壳"的地方。
- 每个功能只说一句「为什么这么做」，不说实现细节。
- 不要演示超过 4 个场景。
