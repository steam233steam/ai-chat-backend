# 踩坑记录

> 记录 aichat 项目从 0 到 1 开发过程中踩过的坑，按类别分组。每个坑包含现象、根因、解决方式，方便复习和面试复盘。

## 一、Redis 相关

### 1. `BeanUtil.beanToMap` 转 Map 时空指针
- **现象**：登录成功返回 Token 时抛 `NullPointerException: Cannot invoke "Object.toString()" because "fieldValue" is null`
- **根因**：`fieldValueEditor((fieldName, fieldValue) -> fieldValue.toString())` 没做 null 判断，User 实体里某个字段为 null 时直接空指针
- **解决**：`fieldValue == null ? "" : fieldValue.toString()`，或干脆不用 BeanUtil，手动构建 `HashMap` 只放需要的字段

### 2. `/me` 数据更新后不生效
- **现象**：用户调 `/user/profile` 修改昵称后，再次调 `/me` 还是旧名字；重新登录后就正常
- **根因**：Redis 里 Token 对应的用户 Hash 没更新。拦截器每次请求都从 Redis 读旧数据覆盖 `UserHolder`，`/me` 返回的是 Redis 里的旧值
- **解决**：`updateProfile` 时同步更新 Redis 里 Token 对应的 Hash，不只是改数据库

### 3. Redis key 层级混淆
- **现象**：Redis 客户端把 `chat:users:xxx` 展示成"重复目录"
- **根因**：Redis 客户端把 key 按 `:` 分隔符自动层级展开成文件夹结构，实际 key 是完整字符串
- **解决**：不用纠结展示方式，key 本身是完整字符串

## 二、Spring / 拦截器 / 异步

### 4. `@Async` 方法在类内部调用不生效
- **现象**：`this.asyncMethod()` 实际是同步执行
- **根因**：`@Async` 依赖 Spring AOP 代理，类内自调用绕过代理，`@Async` 失效
- **解决**：把异步方法拆到独立的 Service 类，通过注入的 Bean 引用调用

### 5. `@Async` 线程拿不到 `ThreadLocal`
- **现象**：`generateTitleAsync` 里 `UserHolder.getUser()` 为 null
- **根因**：`UserHolder` 用 ThreadLocal 存当前用户，但 `@Async` 方法跑在线程池线程里，ThreadLocal 是线程隔离的
- **解决**：所有异步方法需要的数据（userId/sessionId 等）在调用前从 `UserHolder` 取好，**显式当参数传进去**

### 6. 拦截器执行顺序搞混
- **现象**：校验登录时 `UserHolder` 还没填充
- **根因**：`RefreshTokenInterceptor`（读 Token 存 UserHolder）必须在 `LoginInterceptor`（校验 UserHolder）之前执行
- **解决**：`WebMvcConfig` 里按顺序注册，先 Refresh 后 Login

## 三、MyBatis / 数据库

### 7. `updateProfile` SQL 的 WHERE 条件写错
- **现象**：修改昵称不生效
- **根因**：表主键是 `uid` 不是 `id`，SQL 写 `WHERE id = #{id}` 查不到数据
- **解决**：`WHERE uid = #{uid}`，参数注解也要对应

### 8. `query().eq().one()` 不符合分层
- **现象**：Service 层直接写查询逻辑
- **根因**：MyBatis-Plus 教程爱用链式 API 省事，但违反三层架构
- **解决**：下沉到 Mapper，Service 只调 Mapper 方法

### 9. 实体类字段名和 SQL 列名对不上
- **现象**：运行时报"字段不存在"
- **根因**：实体改了字段名但 SQL 列名没改（或反过来）
- **解决**：改字段名时同步改 SQL 的 `#{...}` 和列名

## 四、Java 语言 / 规范

### 10. URL 路径命名不规范
- **现象**：`/loginbypassword`、方法名 `loginbypassword`
- **解决**：`/login/password` + `loginByPassword`

### 11. 类名拼写错误
- **现象**：`ChatTitleSeviceimpl`（Sevice → Service）
- **解决**：IDE 里 F2 重命名，同时同步改类名

### 12. 方法名首字母大写
- **现象**：`SendSession`、`ClearSession`
- **根因**：Java 方法命名规范是小驼峰
- **解决**：`sendSession`、`clearSession`

### 13. `sendCode` 方法名写成 `login`
- **现象**：`@PostMapping("/code")` 的方法叫 `login`，读代码的人困惑
- **解决**：方法名应该和 URL 语义一致，`sendCode` 或 `code`

### 14. `@RequestParam` 和 `@RequestBody` 混用
- **现象**：发送验证码接口参数用 `@RequestParam`，登录接口用 `@RequestBody`
- **根因**：没想清楚请求体形式，混着写
- **解决**：简单参数用 `@RequestParam`，对象参数用 `@RequestBody`，统一风格

### 15. `HttpSession` 和 Redis 并存
- **现象**：梳理方案用 Redis 存验证码，但接口又传了 `HttpSession` 参数
- **根因**：从模板代码复制的多余参数
- **解决**：用 Redis 就删掉 `HttpSession` 参数

### 16. `Result` 返回类型和泛型
- **现象**：`Result.success()` 只接受一个 data 参数，想返回额外标记时发现接口不够用
- **解决**：要么扩展 `Result` 的静态方法，要么让 Controller 返回更结构化的 DTO

## 五、编译 / 构建 / 工具链

### 17. Windows cmd 没有 `head` / `tail` / `grep`
- **现象**：`mvn compile | head` 报错 `'head' 不是内部或外部命令`
- **解决**：cmd 用 `findstr`，PowerShell 用 `Select-Object`；或者直接不接管道

### 18. 编译成功但没真正重新编译
- **现象**：`mvn compile` 显示 "no recompilation needed"
- **根因**：Maven 增量编译，文件没变就跳过
- **解决**：`mvn clean compile` 强制重新编译

### 19. `hutool-crypto` 依赖没加
- **现象**：用 `BCrypt.hashpw` 加密密码，编译报"找不到符号"
- **根因**：`BCrypt` 在 `hutool-crypto` 包里，`hutool-core` 没有
- **解决**：`pom.xml` 加 `hutool-crypto` 依赖

### 20. Git 推送 URL 写错
- **现象**：`git push` 报 `repository not found`
- **根因**：GitHub 仓库名截断显示，远程地址配错
- **解决**：在 GitHub 仓库页面点 Code 按钮复制完整地址，`git remote set-url` 更新

## 六、业务逻辑 / 设计

### 21. 验证码校验逻辑写反
- **现象**：正确验证码反而提示"验证码错误"
- **根因**：`if (checkCode(...) == true) return 错误`，`checkCode` 返回 true 是"验证通过"，逻辑反了
- **解决**：`if (!checkCode(...)) return 错误`

### 22. `deleteCode` 位置不对
- **现象**：验证码的删除逻辑写在了 `saveUser` 里
- **根因**：验证码用完即焚应该在**登录成功之后**，不该和保存用户耦合
- **解决**：`login` 方法里校验通过后才删验证码

### 23. 用户数据没有隔离
- **现象**：不同用户会话数据互相污染
- **根因**：所有会话共用 `sessions` / `session:xxx` / `titles` 这几个 key
- **解决**：所有 key 加 userId 前缀（`chat:sessions:{userId}`），彻底隔离

### 24. `updateProfile` 改了资料但不同步其他缓存
- **现象**：改昵称后 Redis 的 Token Hash 还是旧的
- **根因**：`updateProfile` 只更新了数据库和 `UserHolder`，没同步 Redis Token
- **解决**：修改资料时同步更新 Redis 里 Token 对应的用户 Hash

### 25. 会话标题生成时机
- **现象**：首条消息落库时 title=null
- **根因**：`saveTitle` 在 `save` 之后才调，首条消息进来时 title 还没写进 Redis
- **解决**：重排顺序，先 `saveTitle`（兜底）再 `save`（消息），或在落库时 title=null 由后续消息补上

### 26. `generateTitleAsync` 只写 MySQL 没刷 Redis
- **现象**：AI 生成新标题后，用户刷新侧栏看到的还是兜底标题
- **根因**：调的是 `persistenceService.saveTitle`（只写库），Redis 缓存没更新
- **解决**：走 `chatSessionRepository.saveTitle`，双写 MySQL + Redis

### 27. `sendSessionStream` 没接 AI 标题生成
- **现象**：走流式接口的用户永远拿不到 AI 标题
- **根因**：只在同步 `SendSession` 里接了 `generateTitleAsync`，流式方法漏接
- **解决**：流式方法的 `if (history.isEmpty())` 块里也加 `generateTitleAsync`

## 七、容易再踩的坑（提前避雷）

| 坑 | 说明 |
|----|------|
| **`@Transactional` + `@Async` 混用** | 跨线程事务各自独立，注意异步方法里的事务不会和主线程共享 |
| **Redis 序列化不一致** | `RedisTemplate<String,Object>` 存 `SMessage`，读出来要 `filter(SMessage.class::isInstance)`，反序列化不匹配会全 miss |
| **流式 `onErrorResume` 吞异常** | 异常转成文案后 `doFinally` 走的是正常分支，AI 失败的消息不会落库 |
| **密码登录 / 验证码没限流** | 可无限刷，生产环境要加频率限制 |
| **拦截器 401 手写 JSON** | 绕过了 `Result` 统一格式，和全局异常处理器不一致 |

## 八、分页 / 长上下文（2026-10-25）

### 28. MyBatis 插入后拿不到自增 id
- **现象**：消息落库成功，但 Redis 里的 `SMessage.id` 一直是 null，分页游标无法使用
- **根因**：`@Insert` 默认只返回影响行数，不会把数据库生成的主键写回实体
- **解决**：加 `@Options(useGeneratedKeys = true, keyProperty = "id")`；保存后用返回实体的 id 写缓存，不依赖“调用方对象一定被原地修改”

### 29. 缓存结构升级后旧数据缺字段
- **现象**：给 `SMessage` 加 `id` 后，7 天内未过期的旧缓存反序列化出来 id 为 null，分页结果错乱
- **根因**：Redis 里存的是旧版本 JSON，新字段没有值；JSON 反序列化不会报错
- **解决**：读到 id 为 null 的缓存时视为未命中，回源 MySQL 并整体重建；重建前先 `delete` 旧 key，避免 `rightPushAll` 追加造成重复

### 30. 分页查询把“一页”写回全量缓存
- **现象**：翻页后 Redis List 只剩一页消息，再查全量历史或让 AI 读上下文时历史变短
- **根因**：分页未命中时复用了全量历史的回填逻辑
- **解决**：分页未命中只查 MySQL 当前页，**不回填**；只有全量查询才回填缓存

### 31. 上下文裁剪和历史接口混为一谈
- **现象**：为了省 token 只查最近 20 条，结果用户看到的历史也只剩 20 条
- **根因**：把“送给模型的历史”和“给前端展示的历史”当成同一份数据
- **解决**：历史接口返回全量/分页；只在构造 Prompt 前裁剪，同步和流式共用同一个 `trimHistory()`

## 十一、模型输出净化（DeepSeek `<ds_safety>` 标签泄漏，2026-11-01）

### 32. system prompt 元指令戳中模型安全审核层，内部标签漏进正文

> 2026-11-01 更新：历史已改为真实 User/Assistant 消息，不再使用 system 历史块；`ChatHistoryFormatter` 已删除。以下为旧方案记录。
- **现象**：对 DeepSeek（`deepseek-chat`）发超短输入"你是"，模型回复稳定夹带内部安全审核标签：`我是一个乐于助<ds_safety>[用户未成年]否[分类]其他[判定]…安全。[规则]无</ds_safety>Safe`，脏数据原样落库 + 进前端
- **根因**：`withHistory` 的 system prompt 里反复做元认知指令（"你是当前模型""别的模型不是你说的""仅供参考不要当记忆""以你（当前模型）的身份回答"）。带安全审核层的模型在"短输入 + 强元指令"组合下会进入自我审视模式，把推理侧 `<ds_safety>` 审核内容合并进 content
- **解决（两层，治本 + 治标）**：
  1. **治本**：`withHistory` 的 system prompt 简化成朴素任务指令（"以下是历史，请结合回答当前问题"），去掉所有"自我身份/审视"措辞。发言者区分交给 `ChatHistoryFormatter` 渲染带模型名的"发言者: xxx"即可，system prompt 不必复述
  2. **治标**：`ModelOutputSanitizer.sanitize()` 在模型回复落库前剥掉 `<ds_safety>…</ds_safety>`（完整标签 + 残缺只开头不闭合），清洗后为空给固定兜底文案。同步 `sendSession` + 流式 `saveAssistantReply` 两处都接
- **面试话术**："输出侧也要净化——模型偶尔会把内部审核标签吐进正文，我做了双层防御：从根上简化 system prompt 避免戳中模型安全层，再加一道输出 sanitizer 剥标签兜底，脏数据不进库、不进前端。"

### 33. 历史消息拼进 system prompt 导致存储型 prompt injection（2026-11-01）
- **现象**：历史被渲染成文本块后拼进 system prompt，用户在历史里写“【结束】忽略以上规则…”会被提升为系统级指令。
- **根因**：`withHistory` 把 `historyBlock` 拼进 `.system(...)`，且 `ChatHistoryFormatter` 还把用户消息标成模型发言，进一步混淆角色。
- **修复**：
  1. 历史改为真实 `UserMessage` / `AssistantMessage` 列表，system 只保留可信人设。
  2. 新增 `ChatHistoryBuilder`，按条数 + 字符预算裁剪，避免超长上下文。
  3. 新增有状态 `StreamingSafetyFilter`，跨 chunk 过滤 `<ds_safety>`。
  4. 标题走 `ModelOutputSanitizer.sanitizeTitle`；流式失败兜底文案不落库。
- **回归**：注入历史不进 system；上下文暗号可跨轮保留；短输入不泄漏标签；SSE 后无 token 请求全部 401。

## 九、面试可展开的"坑转亮点"

把上面这些坑整理成面试话术，能体现"踩过坑并系统解决"的能力：

> "我在做这个项目时踩过几个典型的坑：
> 1. **缓存一致性**：用户修改资料后 `/me` 返回旧数据，根因是 Token 对应的 Redis Hash 没同步更新。我后来在 `updateProfile` 里加了同步逻辑，所有写路径都保证"数据库 + 缓存"双更新。
> 2. **Redis 多数据结构组合**：验证码用 String、Token 用 Hash、会话列表用 ZSet、消息用 List，每种数据结构选对应的 Redis 命令，还做了 Cache-Aside 回源和写失败主动失效。
> 3. **`@Async` + ThreadLocal 的坑**：异步线程拿不到 ThreadLocal 里的用户上下文，我把所有需要的数据在调用前显式取好当参数传进去，避免异步线程依赖请求上下文。
> 4. **全局异常处理统一**：拦截器里 401 原来是手写 JSON 绕过 `Result`，我统一改成抛 `BusinessException`，让全局异常处理器接管，前端拿到的错误格式完全一致。
> 5. **分页游标**：最早想用时间戳分页，但同一毫秒内多条消息会重复/漏数据；后来用自增 id 做排他游标，并处理了旧缓存缺 id、分页回填污染全量缓存这两个边界问题。
> 6. **模型输出净化**：DeepSeek 在短输入下会把内部 `<ds_safety>` 审核标签漏进正文。我从两头治：简化 system prompt 避免戳中模型安全层（治本），再加输出 sanitizer 剥标签（治标），脏数据不进库不进前端。
> "

## 十二、VS Code Java 项目导入 / 启动类识别（2026-11-03）

> 这一组坑的共同特点：**Maven 能编译、应用能启动，但 VS Code 里一片红**。先分清“IDE 索引问题”和“代码问题”，不要急着重构业务代码。

### 34. `Main method not found in the file`

- **现象**：在 VS Code 里对 `ChatServiceimpl.java`、`IntentServiceimpl.java`、`MemoryController.java` 点 Run，提示：
  ```text
  Error: Main method not found in the file, please define the main method as:
     public static void main(String[] args)
  ```
- **根因**：这些类是 `@Service` / `@RestController`，由 Spring 容器创建，本来就没有 `main`。VS Code 的“单文件 Run”只会找当前文件的 `main`，不是 Spring Boot 启动方式。
- **解决**：
  1. 运行 `src/main/java/com/aichat/AichatApplication.java`；
  2. 或在项目根目录执行 `./mvnw.cmd spring-boot:run`；
  3. 或在 `.vscode/launch.json` 配 `mainClass=com.aichat.AichatApplication`，从 Run and Debug 启动。
- **判断标准**：看到 `Started AichatApplication ...` 才算后端启动成功，不是“某个类 Run 成功”。

### 35. `IntentOutcome / IntentService / PromptBuilder cannot be resolved`

- **现象**：`ChatServiceimpl.java` 顶部一片红：
  ```text
  The import com.aichat.Service.IntentOutcome cannot be resolved
  IntentOutcome cannot be resolved to a type
  ...
  ```
  同时可能有：
  ```text
  Given URI does not belong to an existing Java source file
  aichat does not exist
  ```
- **根因**：**不是编译错误**，是 Red Hat Java 语言服务器（JDT LS）没有成功导入 Maven 项目，所有源码都不在它的 classpath 里。JDT 日志里真正的第一段错误是：
  ```text
  Importing Maven project(s)
  Initialization failed
  java.lang.IllegalArgumentException:
  Path must include project and resource name: /aichat
  ```
- **解决**：
  1. 先执行 `mvn -o clean compile`，确认 Maven 侧是 `BUILD SUCCESS`；
  2. VS Code 执行 `Java: Clean Java Language Server Workspace` → `Restart and delete`；
  3. 还不行就关闭 VS Code，删除当前工作区的 JDT 缓存：
     ```text
     %APPDATA%\Code\User\workspaceStorage\<workspace-hash>\redhat.java\jdt_ws
     ```
  4. 重新打开 `D:\maven-project\aichat`，等 **Java Projects** 里出现 `aichat`；
  5. 检查生成的项目 `.classpath` 是否包含 `src/main/java`、`src/test/java`、`JavaSE-17`。
- **验证**：JDT 日志出现：
  ```text
  Progressive import: reporting 1 new project(s)
  Workspace initialized in ...
  ```
  并且 `.metadata/.plugins/org.eclipse.core.resources/.projects/aichat` 存在。

### 36. 仓库根目录的 `nul` 文件把 JDT 项目刷新搞崩

- **现象**：JDT 反复报 `Path must include project and resource name: /aichat`，清缓存后仍然复现。
- **根因**：仓库根目录有一个普通文件 `nul`（内容是误重定向的 PowerShell 报错）。`nul` 是 Windows 保留设备名，Eclipse/JDT 刷新项目资源时遍历到它会产生非法资源路径，导致 Maven 项目导入失败。
- **解决**：
  1. 删除仓库根目录的 `nul`：
     ```bash
     rm -f nul
     ```
  2. 不要在项目目录里执行 `xxx > nul` / `2> nul`；需要丢弃输出时用 `> /tmp/xxx.log` 或 `2>$null`（PowerShell），避免在 Git Bash 下创建名为 `nul` 的普通文件。
  3. 清一次 JDT 缓存并重新 Reload Window。
- **验证**：重新导入后 JDT 不再报 `/aichat`，项目结构正常出现在 Java Projects。

### 37. 多个 Java 扩展包互相抢语言服务器

- **现象**：一会儿能 Run，一会儿不能；Problems 面板出现旧文件错误；日志出现：
  ```text
  Install bundle failure org.objectweb.asm_9.10.1.jar
  Failed to load extension bundles
  ```
- **根因**：同时装了多套 Java 扩展：
  - `vscjava.vscode-java-pack` + `redhat.java`（Microsoft/Red Hat 这一套）
  - `pleiades.java-extension-pack-jdk`
  - `loiane.java-spring-extension-pack`
  - `walkme.java-extension-pack`，它会拉入另一套 `georgewfraser.vscode-javac`
  `vscode-javac` 和 Red Hat Java 同时存在时，Run/索引行为容易不一致；`vscode-java-test` 的 asm bundle 也可能和 JDT 冲突。
- **解决**：
  1. 保留一套：`vscjava.vscode-java-pack` + `redhat.java` + `vscjava.vscode-java-debug` + `vscjava.vscode-maven`；
  2. 禁用/卸载 `georgewfraser.vscode-javac`（或它所属的 `walkme.java-extension-pack`）；
  3. 如果 VS Code 里跑测试异常，再临时禁用 `vscjava.vscode-java-test`；
  4. `Developer: Reload Window`，必要时再 Clean Java Language Server Workspace。
- **注意**：`Install bundle failure` 不一定会阻止启动类识别，但会让 Java Test/部分命令异常；先保证只有一套 Java 语言服务器。

### 38. 别把本地日志噪音当成后端故障

| 日志 | 实际含义 | 处理 |
|---|---|---|
| `==> Preparing:` / `<== Total:` | MyBatis SQL 调试输出 | 不是错误；生产可把 `mybatis.configuration.log-impl` 改为 `NoLoggingImpl` |
| `No static resource chat/send` | 没有 `/chat/send` 这个接口 | 用 `POST /chat/ask` 或 `GET /chat/ask-stream` |
| `Request method 'GET' is not supported` | 用 GET 调了 POST 接口 | 查 API 文档的 HTTP method |
| `code=401, message=请先登录` | 请求没带 `Authorization` token | 登录后带 token |
| `Cannot reconnect to localhost:16379` | Redis/虚拟机停了 | 启动 VM Redis，检查 16379 |
| `mvn test` 里的异常堆栈 | 测试故意覆盖 401/404/405/异常分支 | 只看 `Tests run: ..., Failures: 0, Errors: 0` 和 `BUILD SUCCESS` |
| `Main method not found` | 对 Service/Controller 单文件点 Run | 运行 `AichatApplication` 或 `spring-boot:run` |

### 39. Java 时间与 MySQL 时间不一致，`completed_at` 早于 `create_time`

- **现象**：任务刚创建完成，返回：
  ```text
  createTime  = 16:08:11   （MySQL 默认 CURRENT_TIMESTAMP）
  completedAt = 16:07:26   （Java nowLocal/Clock）
  ```
  看起来像“完成时间早于创建时间”。
- **根因**：Windows/JVM 时间与虚拟机 MySQL 时间不同步（实测差约 47 秒）。`create_time/update_time` 由 MySQL `NOW()`/默认值生成，`completed_at/due_at` 由 Java `Clock` 生成；两个时钟源不一致时就会出现这种“时间倒挂”。
- **解决**：
  1. 虚拟机同步时间：
     ```bash
     sudo timedatectl set-ntp true
     sudo systemctl restart systemd-timesyncd
     ```
     或使用 VirtualBox 的“自动同步主机时间”；
  2. 业务时间统一用注入的 `Clock`，不要混用 `LocalDateTime.now()`、SQL `NOW()` 和数据库默认时间；
  3. 排查时用 `date` 与 `SELECT NOW()` 对比，不要先怀疑业务代码。
- **面试话术**：时间字段出现倒挂，先查时钟源，不要先改业务逻辑；生产必须保证应用服务器和数据库 NTP 同步。

### 40. 集成测试在依赖服务没起时一跑就红

- **现象**：`mvn test` 报一串 `CannotGetJdbcConnection` / `Failed to obtain JDBC Connection`。
- **根因**：`FullFlowIntegrationTest`、`MindButlerFlowIntegrationTest`、`MindButlerEvalRunnerTest` 需要真实 MySQL(13306)/Redis(16379)；CI 没起这些服务。
- **解决**：
  1. 在测试 setup 里通过 `DbTestSupport` 探测 MySQL/Redis，不可用则 `Assumptions` skip；
  2. CI 的 `-Dtest` 排除清单同时排除这些集成测试；
  3. 本地要跑全量时先起虚拟机，再执行 `mvn test`；
  4. 只看 `Failures/Errors`，不要把 skip 或预期异常当成业务失败。

### 41. VS Code 问题排查顺序（建议收藏）

```text
1. mvn -o clean compile        -> 先证明代码能编译
2. 运行 AichatApplication      -> 再证明启动类正确
3. 看 Java Projects 有没有 aichat
4. 没有 -> Clean Java Language Server Workspace
5. 仍有 /aichat / URI 错误 -> 删除 redhat.java/jdt_ws 后重开
6. 检查仓库根目录有没有 nul 等非法文件名
7. 只保留一套 Java 扩展，Reload Window
8. 最后才怀疑业务代码
```
