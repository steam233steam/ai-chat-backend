# 踩坑记录

> 记录 aichat 项目从 0 到 1 开发过程中踩过的坑，按类别分组。每个坑包含现象、根因、解决方式，方便复习和面试复盘。

## 一、Redis 相关

### 1. `BeanUtil.beanToMap` 转 Map 时空指针
- **现象**：登录成功返回 Token 时抛 `NullPointerException: Cannot invoke "Object.toString()" because "fieldValue" is null`
- **根因**：`fieldValueEditor((fieldName, fieldValue) -> fieldValue.toString())` 没做 null 判断，User 实体里某个字段为 null 时直接空指针
- **解决**：`fieldValue == null ? "" : fieldValue.toString()`，或干脆不用 BeanUtil，手动构建 `HashMap` 只放需要的字段

### 2. `/me` 数据更新后不生效
- **现象**：用户调 `/user/profile` 修改昵称后，再次调 `/me` 还是旧名字；重新登录后就正常
- **根因**：Redis 里 Token 对应的用户 Hash 没更新。拦截器每次请求都从 Redis 读旧数据覆盖 `UserHolder`，`/me` 返回的是 Redis 里的旧值
- **解决**：`updateProfile` 时同步更新 Redis 里 Token 对应的 Hash，不只是改数据库

### 3. Redis key 层级混淆
- **现象**：Redis 客户端把 `chat:users:xxx` 展示成"重复目录"
- **根因**：Redis 客户端把 key 按 `:` 分隔符自动层级展开成文件夹结构，实际 key 是完整字符串
- **解决**：不用纠结展示方式，key 本身是完整字符串

## 二、Spring / 拦截器 / 异步

### 4. `@Async` 方法在类内部调用不生效
- **现象**：`this.asyncMethod()` 实际是同步执行
- **根因**：`@Async` 依赖 Spring AOP 代理，类内自调用绕过代理，`@Async` 失效
- **解决**：把异步方法拆到独立的 Service 类，通过注入的 Bean 引用调用

### 5. `@Async` 线程拿不到 `ThreadLocal`
- **现象**：`generateTitleAsync` 里 `UserHolder.getUser()` 为 null
- **根因**：`UserHolder` 用 ThreadLocal 存当前用户，但 `@Async` 方法跑在线程池线程里，ThreadLocal 是线程隔离的
- **解决**：所有异步方法需要的数据（userId/sessionId 等）在调用前从 `UserHolder` 取好，**显式当参数传进去**

### 6. 拦截器执行顺序搞混
- **现象**：校验登录时 `UserHolder` 还没填充
- **根因**：`RefreshTokenInterceptor`（读 Token 存 UserHolder）必须在 `LoginInterceptor`（校验 UserHolder）之前执行
- **解决**：`WebMvcConfig` 里按顺序注册，先 Refresh 后 Login

## 三、MyBatis / 数据库

### 7. `updateProfile` SQL 的 WHERE 条件写错
- **现象**：修改昵称不生效
- **根因**：表主键是 `uid` 不是 `id`，SQL 写 `WHERE id = #{id}` 查不到数据
- **解决**：`WHERE uid = #{uid}`，参数注解也要对应

### 8. `query().eq().one()` 不符合分层
- **现象**：Service 层直接写查询逻辑
- **根因**：MyBatis-Plus 教程爱用链式 API 省事，但违反三层架构
- **解决**：下沉到 Mapper，Service 只调 Mapper 方法

### 9. 实体类字段名和 SQL 列名对不上
- **现象**：运行时报"字段不存在"
- **根因**：实体改了字段名但 SQL 列名没改（或反过来）
- **解决**：改字段名时同步改 SQL 的 `#{...}` 和列名

## 四、Java 语言 / 规范

### 10. URL 路径命名不规范
- **现象**：`/loginbypassword`、方法名 `loginbypassword`
- **解决**：`/login/password` + `loginByPassword`

### 11. 类名拼写错误
- **现象**：`ChatTitleSeviceimpl`（Sevice → Service）
- **解决**：IDE 里 F2 重命名，同时同步改类名

### 12. 方法名首字母大写
- **现象**：`SendSession`、`ClearSession`
- **根因**：Java 方法命名规范是小驼峰
- **解决**：`sendSession`、`clearSession`

### 13. `sendCode` 方法名写成 `login`
- **现象**：`@PostMapping("/code")` 的方法叫 `login`，读代码的人困惑
- **解决**：方法名应该和 URL 语义一致，`sendCode` 或 `code`

### 14. `@RequestParam` 和 `@RequestBody` 混用
- **现象**：发送验证码接口参数用 `@RequestParam`，登录接口用 `@RequestBody`
- **根因**：没想清楚请求体形式，混着写
- **解决**：简单参数用 `@RequestParam`，对象参数用 `@RequestBody`，统一风格

### 15. `HttpSession` 和 Redis 并存
- **现象**：梳理方案用 Redis 存验证码，但接口又传了 `HttpSession` 参数
- **根因**：从模板代码复制的多余参数
- **解决**：用 Redis 就删掉 `HttpSession` 参数

### 16. `Result` 返回类型和泛型
- **现象**：`Result.success()` 只接受一个 data 参数，想返回额外标记时发现接口不够用
- **解决**：要么扩展 `Result` 的静态方法，要么让 Controller 返回更结构化的 DTO

## 五、编译 / 构建 / 工具链

### 17. Windows cmd 没有 `head` / `tail` / `grep`
- **现象**：`mvn compile | head` 报错 `'head' 不是内部或外部命令`
- **解决**：cmd 用 `findstr`，PowerShell 用 `Select-Object`；或者直接不接管道

### 18. 编译成功但没真正重新编译
- **现象**：`mvn compile` 显示 "no recompilation needed"
- **根因**：Maven 增量编译，文件没变就跳过
- **解决**：`mvn clean compile` 强制重新编译

### 19. `hutool-crypto` 依赖没加
- **现象**：用 `BCrypt.hashpw` 加密密码，编译报"找不到符号"
- **根因**：`BCrypt` 在 `hutool-crypto` 包里，`hutool-core` 没有
- **解决**：`pom.xml` 加 `hutool-crypto` 依赖

### 20. Git 推送 URL 写错
- **现象**：`git push` 报 `repository not found`
- **根因**：GitHub 仓库名截断显示，远程地址配错
- **解决**：在 GitHub 仓库页面点 Code 按钮复制完整地址，`git remote set-url` 更新

## 六、业务逻辑 / 设计

### 21. 验证码校验逻辑写反
- **现象**：正确验证码反而提示"验证码错误"
- **根因**：`if (checkCode(...) == true) return 错误`，`checkCode` 返回 true 是"验证通过"，逻辑反了
- **解决**：`if (!checkCode(...)) return 错误`

### 22. `deleteCode` 位置不对
- **现象**：验证码的删除逻辑写在了 `saveUser` 里
- **根因**：验证码用完即焚应该在**登录成功之后**，不该和保存用户耦合
- **解决**：`login` 方法里校验通过后才删验证码

### 23. 用户数据没有隔离
- **现象**：不同用户会话数据互相污染
- **根因**：所有会话共用 `sessions` / `session:xxx` / `titles` 这几个 key
- **解决**：所有 key 加 userId 前缀（`chat:sessions:{userId}`），彻底隔离

### 24. `updateProfile` 改了资料但不同步其他缓存
- **现象**：改昵称后 Redis 的 Token Hash 还是旧的
- **根因**：`updateProfile` 只更新了数据库和 `UserHolder`，没同步 Redis Token
- **解决**：修改资料时同步更新 Redis 里 Token 对应的用户 Hash

### 25. 会话标题生成时机
- **现象**：首条消息落库时 title=null
- **根因**：`saveTitle` 在 `save` 之后才调，首条消息进来时 title 还没写进 Redis
- **解决**：重排顺序，先 `saveTitle`（兜底）再 `save`（消息），或在落库时 title=null 由后续消息补上

### 26. `generateTitleAsync` 只写 MySQL 没刷 Redis
- **现象**：AI 生成新标题后，用户刷新侧栏看到的还是兜底标题
- **根因**：调的是 `persistenceService.saveTitle`（只写库），Redis 缓存没更新
- **解决**：走 `chatSessionRepository.saveTitle`，双写 MySQL + Redis

### 27. `sendSessionStream` 没接 AI 标题生成
- **现象**：走流式接口的用户永远拿不到 AI 标题
- **根因**：只在同步 `SendSession` 里接了 `generateTitleAsync`，流式方法漏接
- **解决**：流式方法的 `if (history.isEmpty())` 块里也加 `generateTitleAsync`

## 七、容易再踩的坑（提前避雷）

| 坑 | 说明 |
|----|------|
| **`@Transactional` + `@Async` 混用** | 跨线程事务各自独立，注意异步方法里的事务不会和主线程共享 |
| **Redis 序列化不一致** | `RedisTemplate<String,Object>` 存 `SMessage`，读出来要 `filter(SMessage.class::isInstance)`，反序列化不匹配会全 miss |
| **流式 `onErrorResume` 吞异常** | 异常转成文案后 `doFinally` 走的是正常分支，AI 失败的消息不会落库 |
| **密码登录 / 验证码没限流** | 可无限刷，生产环境要加频率限制 |
| **拦截器 401 手写 JSON** | 绕过了 `Result` 统一格式，和全局异常处理器不一致 |

## 八、面试可展开的"坑转亮点"

把上面这些坑整理成面试话术，能体现"踩过坑并系统解决"的能力：

> "我在做这个项目时踩过几个典型的坑：
> 1. **缓存一致性**：用户修改资料后 `/me` 返回旧数据，根因是 Token 对应的 Redis Hash 没同步更新。我后来在 `updateProfile` 里加了同步逻辑，所有写路径都保证"数据库 + 缓存"双更新。
> 2. **Redis 多数据结构组合**：验证码用 String、Token 用 Hash、会话列表用 ZSet、消息用 List，每种数据结构选对应的 Redis 命令，还做了 Cache-Aside 回源和写失败主动失效。
> 3. **`@Async` + ThreadLocal 的坑**：异步线程拿不到 ThreadLocal 里的用户上下文，我把所有需要的数据在调用前显式取好当参数传进去，避免异步线程依赖请求上下文。
> 4. **全局异常处理统一**：拦截器里 401 原来是手写 JSON 绕过 `Result`，我统一改成抛 `BusinessException`，让全局异常处理器接管，前端拿到的错误格式完全一致。
> "
