## 1. P0：先让"能部署、能复现"成立（约 2 天）

现在最脆的地方不是功能，是**换台机器就跑不起来**。

### 1.1 Testcontainers 替掉硬连的 `localhost:13306`

- **现状**：`pom.xml` 装了 Testcontainers 依赖，但 `FullFlowIntegrationTest`、`MindButlerFlowIntegrationTest` 直接连 `localhost:13306`（VirtualBox NAT 转发），虚拟机不开 → 8 个集成测试红。
- **做法**：`@Testcontainers` + `MySQLContainer` + `GenericContainer(redis)`；`@DynamicPropertySource` 注入 `spring.datasource.url` / `spring.data.redis.*`；容器复用 `withReuse(true)` 减少启动开销。Ollama 相关用例继续用 `@DisabledIf` 或本地 profile 兜底。
- **完成定义**：虚拟机关掉，`./mvnw -o test` 仍是 309 绿；CI 里也能跑集成测试。
- **风险**：国内拉镜像慢 → 配镜像源，或用 `GenericContainer` + 本地已有镜像。

### 1.2 `docker-compose.yml` 一键起依赖

- **现状**：部署靠"虚拟机 + NAT 端口映射"，README 里要解释一堆。
- **做法**：compose 起 `mysql:8`（挂 `docs/schema.sql` 初始化）、`redis:7`；后端单独跑或一起 compose。`.env` 管密码。
- **完成定义**：新机器 `git clone` → `docker compose up -d` → `./mvnw spring-boot:run` → 前端能登录。
- **顺带**：把 `docs/本地启动.md` 改写成"两条路径"（Docker 优先，虚拟机作为备选）。

## 2. P1：补齐"说得出彩"的两块（约 3 天）

### 2.1 任务改期 / 取消（对话内）

- **为什么**：记忆能改能删，任务却只能去列表点——这是最明显的功能不对称，面试一问就露。
- **做法**：复用 `MemoryChangeParser` 的骨架写 `TaskChangeParser`：识别「把作业提醒改到明天九点」「取消明天的提醒」，产出 `task_change` 类型的待确认动作；确认时走 `TaskService.update`（已有 `version` 乐观锁）。
- **难点**：时间是相对表述（明天九点 / 后天 / 下周一），要复用现有的 `LocalDateTime` 解析与 `task.zone` 校验；重复任务改期要考虑"只改这一次"还是"改整条"——**先只支持单次任务**，重复任务直接回"请到任务列表改"。
- **完成定义**：单次任务能通过对话改时间/取消，确认后列表与提醒都跟着变，测试覆盖解析 + 落库 + 回执。

### 2.2 部署脚本化

- **做法**：`deploy/` 下放 `nginx.conf`、`mindbutler.service`（systemd）、`deploy.sh`（打包 jar → scp → 重启 → reload nginx）；README 给三步命令。
- **完成定义**：改完代码一条命令上线，回滚就是 `git reset` + 再跑一次。

## 5. 已知技术债（记录，不修）

- **手写 token 拦截器**而非 Spring Security：`RefreshTokenInterceptor` + `LoginInterceptor` + `UserHolder`。换 Security 要重写 200 行 + 全套测试，收益只有"简历上好看"，暂不动。
- **`action_type` 用 VARCHAR 而非 ENUM**：为支持 `memory_change` 改的，语义约束靠代码校验。
- **`DailyRateLimiter` 的进程内降级**：Redis 挂了会退化成单机计数，多实例下不准——单机部署无所谓。
- **MCP 服务器进程常驻**：`McpToolCatalog` 启动即拉起，没有空闲回收；工具少时无所谓。
- **前端 8 处 `catch` 兜底**：网络错误统一横幅提示，单条消息的细粒度错误还没做。
