> 整理日期：2026-11-06　｜　**阶段定义**以 `MindButler-P1设计.md` §11 为准，本文件只负责"先做哪个、为什么、不做什么"。

## 0. 定位

> 带 AI 能力、有缓存/持久化设计、能测试、能部署的 Spring Boot 后端。
> 差异化不在业务广度，在工程深度——业务简单是为了把技术做深。

两条线，一个终点：

| 线 | 目标 | 用途 |
|---|---|---|
| **工程线**（主轴） | 让它"能讲清楚" | 决定面试成败：可靠性、工程化、可解释 |
| **产品线**（素材） | 让它"能用" | 提供 AI 深度的讲法：记忆、意图、提醒 |

产品线只取低成本高价值的部分并入工程线，其余推迟到面试之后。

## 3. 明确不做（写下来防"手痒"）

| 事项 | 原因 |
|---|---|
| MCP 接米游社等第三方数据 | 接口不稳定、可能要逆向，面试 ROI≈0，成本 5+ 天（维持 P2 但排在最后） |
| 微信 / QQ 客服推送 | 需企业主体与备案，个人做不了；P3 里邮件/Webhook 已足够讲可靠性 |
| outbox / MQ / 微服务化 / Kafka / K8s | 这个规模不需要，讲不出"为什么"就是减分 |
| 管理员后台（纯 CRUD） | 除非做成 RBAC + 审计日志，否则 2 天买不到面试分 |
| 商业化代码 | 写 300 字商业模型进 README 即可，不写代码（P4 是 memo） |
| 会话冷热分离 | 已有 Cache-Aside + TTL，收益递减 |

## 4. 已知矛盾与修正（旧文档里的错误结论）

| 旧说法 | 实际 |
|---|---|
| INTERVIEW_ROADMAP：「缺 Swagger / 限流 / Docker」 | springdoc 已在 `pom.xml`；限流已有 `IntentDailyLimiter`；Docker 确实还没做 |
| 「环境是 Docker Desktop」 | 实际是 **VirtualBox 虚拟机 `studybox`(Ubuntu 22.10) + NAT 转发**：MySQL 3306→宿主 13306，Redis 6379→宿主 16379 |
| DEVELOPMENT_PLAN 原则：「集成测试不要依赖本机已启动的服务」 | 两个集成测试**硬连** `localhost:13306`，虚拟机/容器没起就报 `Connection refused` |
| 「Task/User Service 没有事务是硬伤」 | 核实后：写都是单语句（`insert` / `updateByIdAndVersion` / `softDelete`），加 `@Transactional` 只是形式。真正需要的只有 `createWithReplaces`（已修）与 `PendingActionServiceImpl`（本来就有） |
| 「记忆幂等删除判断是 bug」 | 误报：`selectById` 不过滤 `status`，软删行仍能查到，`rows>0 \|\| selectById!=null` 是对的 |
