## 30 秒版本（自我介绍时）

> 我做了个 AI 助手后端，重点不是接模型，而是让"聊天里说的话能真的落成数据和操作"：
> 说"记住我喜欢简洁"会弹确认框、确认才写；说"下周三交作业"会变成任务；
> 要查天气它能自己调工具。为了可撤销和可测，所有写操作都先出预览再确认。

## 9 个高频追问

| 追问 | 怎么答（要点） |
|---|---|
| 为什么不用 Spring Security？ | 演示项目要能讲清登录态就是"Redis 里的一个 token + hash"，Security 的过滤器链对读者是黑盒。代价：越权校验、BCrypt、401/403 都得自己写，我写了拦截器和单测覆盖 |
| 为什么"记住"要多一步确认？ | 模型会猜错，删除不可逆；多一步是给用户撤销的机会。实现上复用同一套 pending 状态机，幂等（重复确认不重复写） |
| 记忆衰减为什么查询时算？ | 定时任务要处理没跑/跑重/时区三类问题，现算没有一致性问题；代价是每次注入多几次运算、不能按权重建索引 |
| 怎么保证长对话不爆上下文？ | 只注入最近 N 条 + 记忆最多 5 条；候选池放大 3 倍再按权重截断，避免只按旧顺序截断导致高权重记忆被挤掉 |
| 流式怎么实现？ | `Flux<String>` → SSE；前端手写了解析器（保留 `data:` 后空格，防英文单词粘连） |
| 为什么 SSE 要改 POST？ | GET 把 question 放 URL，撞网关长度上限、还进访问日志；旧的 GET 保留但标记废弃，兼容集成测试 |
| 工具调用怎么接的？ | 自实现 MCP 客户端（BOM 里没有 MCP 模块，升级成本高），stdio + 换行 JSON-RPC、超时、服务端反向请求回 -32601、单服务失败只 warn |
| 并发问题考虑了吗？ | pending 有唯一键 + 重复确认幂等 + `version` 乐观锁；限流 Redis 挂了降级进程内计数 |
| 测试怎么保证？ | 309 个，三层：纯单测（Mockito）、工具类、8 个真实连 MySQL/Redis 的集成测试；12 条人工验收用例逐条执行留档 |

## 已知短板（主动说出来，比被问出来好）

- 没有 Docker Compose / Nginx 配置，部署靠手工（路线图里有排期）
- 集成测试硬连 `localhost:13306`（虚拟机 NAT），换机器要改配置
- 意图识别是关键词 + 固定 schema 提取，没做 LLM 分类对比（需要评测集才有意义）
- 任务的改时间 / 删除还没做，聊天里只引导到任务列表
- 前端 SSE 解析器是自己写的，没做重连与断点续传
