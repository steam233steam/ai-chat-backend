## 1. 项目概述

### 1.1 项目简介

一个基于 Spring Boot + Spring AI + Redis 的 AI 聊天应用，支持多轮对话，对话历史存储在 Redis 中。

### 1.2 技术栈

| 组件 | 版本 |
|------|------|
| Spring Boot | 3.2.5 |
| Java | 17 |
| Spring AI | 1.0.0-M5 |
| Redis | 7.x (端口 16379) |
| Ollama | 本地运行 (qwen2.5-coder:7b) |
| Lombok | 1.18.32 |

### 1.3 核心依赖

```xml
<dependencies>
    <!-- Spring Boot Web -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    
    <!-- Spring Data Redis -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-redis</artifactId>
    </dependency>
    
    <!-- Spring AI Ollama -->
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-ollama-spring-boot-starter</artifactId>
    </dependency>
    
    <!-- Lombok -->
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>
</dependencies>
```

### 2.2 Redis Key 设计

```
# 会话消息历史（List 结构）
chat:session:{sessionid}
    ↓
    List<SMessage>
    ├── SMessage{text="你好", type="user"}
    ├── SMessage{text="你好！我是AI助手...", type="assistant"}
    └── SMessage{text="请问有什么可以帮助你的？", type="assistant"}
    
TTL: 7天

# 会话列表（ZSet 结构，按时间戳排序）
chat:sessions
    ↓
    ZSet{sessionid1 → timestamp1, sessionid2 → timestamp2, ...}
    
TTL: 7天

# 会话标题（Hash 结构）
chat:session:titles
    ↓
    Hash{sessionid1 → "用户你好", sessionid2 → "Java学习", ...}
    
TTL: 7天
```

### 2.3 为什么这样设计？

| 数据结构 | 用途 | 原因 |
|---------|------|------|
| **List** | 存储消息历史 | 天然保持时序性，支持流式追加 |
| **ZSet** | 存储会话列表 | 按时间戳排序，最新会话置顶 |
| **Hash** | 存储会话标题 | 一对多映射，查询效率高 |

## 3. 核心机制

### 3.1 消息序列化与反序列化

**存储（Java → Redis）：**
```java
// Spring AI Message → SMessage → Redis JSON
SMessage sMessage = new SMessage(message.getText(), type);
redisTemplate.opsForList().rightPush(key, sMessage);
```

**读取（Redis → Java）：**
```java
// Redis JSON → SMessage → Spring AI Message
List<Object> messages = redisTemplate.opsForList().range(key, 0, -1);
List<Message> history = messages.stream()
    .filter(obj -> obj instanceof SMessage)
    .map(obj -> (SMessage) obj)
    .map(sMessage -> switch (sMessage.getType()) {
        case "user" -> new UserMessage(sMessage.getText());
        case "assistant" -> new AssistantMessage(sMessage.getText());
        case "system" -> new SystemMessage(sMessage.getText());
        default -> throw new IllegalArgumentException("未知消息类型: " + sMessage.getType());
    })
    .collect(Collectors.toList());
```

### 3.2 Java 17 特性使用

1. **Switch 表达式** - 消息类型转换
2. **instanceof 模式匹配** - 类型判断
3. **Records / List.of()** - 不可变集合
4. **文本块** - 多行字符串

### 3.3 多态应用

```java
// 接口定义
public interface ChatSessionRepository {
    void save(String sessionid, Message message);
    List<Message> getHistory(String sessionid);
}

// 实现类使用多态
@Override
public void save(String sessionid, Message message) {
    String type = getMessageType(message); // instanceof 判断
    SMessage sMessage = new SMessage(message.getText(), type);
    redisTemplate.opsForList().rightPush(key, sMessage);
}

private String getMessageType(Message message) {
    if (message instanceof UserMessage) return "user";
    if (message instanceof AssistantMessage) return "assistant";
    if (message instanceof SystemMessage) return "system";
    return "unknown";
}
```

### 3.4 会话标题生成策略

**自动标题：** 首次对话时，取用户问题前10字作为标题
```java
if (history.size() == 1) {
    String question = userMessage.getText();
    String title = question.length() > 10 ? question.substring(0, 10) + "..." : question;
    chatSessionRepository.saveTitle(sessionid, title);
}
```

**手动更新：** 用户可通过接口自定义标题
```java
@PutMapping("/title")
public Result updateTitle(@RequestParam String sessionid, @RequestParam String title) {
    chatService.saveTitle(sessionid, title);
    return Result.success("标题更新成功");
}
```

## 4. 踩坑记录

### 4.1 RedisTemplate Bean 冲突

**报错：**
```
Error creating bean with name 'chatSessionRepositoryimpl': 
Unsatisfied dependency expressed through field 'RedisTemplate': 
No qualifying bean of type 'RedisTemplate<?, ?>' available: 
expected single matching bean but found 2: redisTemplate, stringRedisTemplate
```

**原因：** Spring Boot 自动配置同时提供了 `redisTemplate` 和 `stringRedisTemplate` 两个 bean，注入时发生歧义。

**解决方案：** 使用 `@Qualifier` 指定要注入的 bean：

```java
@Autowired
@Qualifier("redisTemplate")
private RedisTemplate<String, Object> redisTemplate;
```

**进阶说明：** 更彻底的解法是自定义 Bean 名称避免冲突：

```java
@Bean("chatRedisTemplate")
public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
    RedisTemplate<String, Object> template = new RedisTemplate<>();
    template.setConnectionFactory(factory);
    template.setKeySerializer(new StringRedisSerializer());
    template.setHashKeySerializer(new StringRedisSerializer());
    template.afterPropertiesSet();
    return template;
}
```

### 4.2 ChatClient 包名错误（非版本问题）

**报错：**
```
The import org.springframework.ai.client cannot be resolved
ChatClient cannot be resolved to a type
```

**原因：** **不是版本问题！** 是包名写错了。`ChatClient` 在 M5 版本已经存在，正确包名是：

```java
import org.springframework.ai.chat.client.ChatClient;  // ✅ 正确
// import org.springframework.ai.client.ChatClient;    // ❌ 错误，少了一层 chat
```

**解决方案：** 使用正确的包名，并配置 ChatClient bean：

```java
@Configuration
public class ChatClientConfig {
    @Bean
    public ChatClient chatClient(ChatClient.Builder chatClientBuilder) {
        return chatClientBuilder
                .defaultSystem("你是一个有用的助手")
                .build();
    }
}
```

### 4.3 Redis 序列化问题

**报错：**
```
Could not read JSON: Cannot construct instance of `com.aichat.Dto.SMessage` 
(no Creators, like default constructor, exist)
```

**原因：** Redis 使用 Jackson 序列化/反序列化对象时，需要无参构造函数。去掉了 Lombok 的 `@NoArgsConstructor` 后，Jackson 无法创建对象。

**解决方案：** 确保 DTO 类包含无参构造函数：

```java
@AllArgsConstructor
@NoArgsConstructor
@Data
public class SMessage {
    private String text;
    private String type;
}
```

### 4.4 Lombok 注解处理器配置问题

**报错：**
```
Resolution of annotationProcessorPath dependencies failed: 
version can neither be null, empty nor blank
```

**原因：** Maven 编译器插件配置了 `annotationProcessorPaths` 但没有指定 Lombok 版本。

**解决方案：** 移除 `annotationProcessorPaths` 配置，让 Spring Boot 父 POM 管理版本：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <source>17</source>
        <target>17</target>
    </configuration>
</plugin>
```

### 4.5 类名与文件名不一致

**报错：**
```
类 ChatServiceimpl 是公共的, 应在名为 ChatServiceimpl.java 的文件中声明
```

**原因：** 类声明为 `public` 但文件名是 `ChatServiceImpl.java`（大小写不一致）。

**解决方案：** 统一命名规范，类名和文件名完全一致：

```java
// ✅ 正确：文件名 ChatServiceImpl.java，类名 ChatServiceImpl
public class ChatServiceImpl implements ChatService { }

// ❌ 错误：文件名 ChatServiceImpl.java，类名 ChatServiceimpl
public class ChatServiceimpl implements ChatService { }
```

**注意：** 去掉 `public` 修饰符只是绕过编译器检查，会导致类在其他包不可见，**不是正确做法**。

### 4.6 Maven BOM 版本不存在

**报错：**
```
Non-resolvable import POM: The following artifacts could not be resolved: 
org.springframework.ai:spring-ai-bom:pom:1.0.0-GA (absent)
```

**原因：** `1.0.0-GA` 版本不存在，Spring AI 的正式 GA 版本发布时间晚于项目配置时间。

**解决方案：** 使用已发布的稳定版本，如 `1.0.0-M5`：

```xml
<spring-ai.version>1.0.0-M5</spring-ai.version>
```

### 4.7 IDEA/VSCode 索引不同步

**现象：** IDE 显示大量报错但 Maven 编译成功

**解决方案：**
1. 刷新 Maven 依赖：右键 `pom.xml` → Maven → Reload Project
2. 清理 IDE 缓存：File → Invalidate Caches → Invalidate and Restart
3. 重新构建：Build → Rebuild Project

### 4.8 Redis 连接被中止

**现象：**
```
WARN - Cannot reconnect to [localhost/<unresolved>:16379]
INFO - Reconnected to localhost/<unresolved>:16379
```

**原因：** Lettuce 客户端自动重连机制，首次连接可能超时或网络抖动。

**影响：** 不影响功能，最终会自动重连成功。

## 6. 面试可能追问的问题

### Q1: 为什么用 Redis List 而不是 Hash 存储对话历史？

**A:** 
- List 天然保持消息的时序性
- `rightPush` + `range` 可以方便地获取完整对话历史
- 支持流式追加，符合对话场景
- Hash 更适合键值对存储，不适合有序序列

### Q2: 会话列表为什么用 ZSet 而不是 List？

**A:** 
- ZSet 可以按时间戳排序，最新会话自动置顶
- List 需要手动排序，且不支持按分数查询
- ZSet 的 `reverseRange` 操作是 O(log(n) + m)，效率高

### Q3: 对话历史过长怎么办？

**A:** 
- 当前实现无限制存储，实际项目中需要实现裁剪策略
- 方案1：只保留最近 N 条消息（滑动窗口）
- 方案2：对长对话进行摘要压缩
- 方案3：使用向量数据库存储历史，按需检索

### Q4: Redis 序列化用什么方案？为什么？

**A:** 
- 使用 Jackson2JsonRedisSerializer 序列化 Java 对象
- 需要类有无参构造函数（@NoArgsConstructor）
- 需要类有 @Type 标识（GenericJackson2JsonRedisSerializer 自动添加）
- 备选方案：FastJson、Kryo（性能更好但兼容性差）

### Q5: 多用户会话如何隔离？

**A:** 
- 当前设计：`chat:session:{sessionid}`
- 多用户场景：`chat:user:{userId}:session:{sessionId}`
- 或者使用 Hash 结构：`chat:sessions:{userId}` 存储该用户的所有会话 ID

### Q6: Spring AI 的 ChatClient 和 OllamaChatModel 有什么区别？

**A:**
- `ChatClient` 是 Spring AI 高层 API，支持多种模型，API 更简洁
- `OllamaChatModel` 是 Ollama 专用实现，功能更底层
- M5 版本两者都可用，GA 版本主要推荐使用 ChatClient
- ChatClient 支持链式调用，代码更可读
